Committing pushes the updated data straight to GitHub, which redeploys the live site automatically (usually under a minute). The token is used only for this request and never stored anywhere — a fine-grained token scoped to just this repo with Contents: Read and write is enough. If you also want to use the "Refresh media data now" option after committing (fetches ratings/poster/blurb for anything you just added, instead of waiting for the weekly schedule), your token needs Actions: Read and write too.
